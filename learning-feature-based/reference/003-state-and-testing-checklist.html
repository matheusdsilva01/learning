Estado, cache e teste

Decisões rápidas para ownership, mutations otimistas e integração HTTP.

Classificar estado

PerguntaSe sim
É autoridade externa e muda sem ação local?Server state; use fetch/cache apropriado.
Precisa sobreviver a reload ou ser compartilhado?URL ou persistência explícita.
Existe apenas para uma interação visual?Estado local; não promova cedo.
Múltiplos clientes alteram simultaneamente?Modele concorrência e reconciliação.

Query key

const productKeys = {
  all: ['products'] as const,
  list: (filters: ProductFilters) => [...productKeys.all, 'list', filters] as const,
  detail: (id: string) => [...productKeys.all, 'detail', id] as const,
}
  • Array no nível superior.
  • Toda variável que altera a `queryFn` entra na chave.
  • Use prefixo sabendo que invalidação faz matching parcial por padrão.
  • `as const` melhora inferência; não garante unicidade global.

Mutation otimista

  1. Decida se UI por `variables` já resolve.
  2. Cancele refetch concorrente da chave afetada.
  3. Capture snapshot.
  4. Atualize imutavelmente.
  5. Retorne o snapshot de `onMutate`.
  6. Restaure em `onError`.
  7. Retorne a Promise de `invalidateQueries` em `onSettled`.
  8. Teste sucesso, falha e, se relevante, concorrência.

Teste de integração

  • Crie `const user = userEvent.setup()` antes da interação.
  • Priorize `getByRole` e nome acessível.
  • Espere um estado que confirme conclusão, não apenas a fase otimista.
  • Sobrescreva handler com `server.use` para erro específico.
  • Não afirme que MSW testou API, banco ou autenticação reais.
Co-localização com limite

Teste e handler específicos podem acompanhar a feature. Setup do runner e utilitários de render continuam centrais. Remover a feature pode exigir atualizar esse ponto de integração.
