Referência 001 / Decisão

Mapa de fronteira de feature

Perguntas para classificar artefatos sem transformar heurísticas em leis.

Fluxo de decisão

O artefato existe por causa de uma capacidade de negócio?
├─ não → é infraestrutura ou primitivo realmente agnóstico?
│        ├─ sim → shared
│        └─ não → mantenha perto do primeiro consumidor
└─ sim → qual capacidade responde por sua mudança?
         ├─ uma feature → mantenha dentro dela
         ├─ conceito estável usado por capacidades diferentes → avalie entity
         └─ colaboração entre features → componha em app/composer

Depois pergunte:
• quem é o owner?
• quais arquivos mudam junto?
• qual contrato externo é necessário?
• qual ambiente executa o módulo?

Mapa por evidência

EvidênciaFavoreceNão prova
Arquivos mudam juntos em requisitos sucessivosCo-localizaçãoNome ou granularidade final
Consumidores precisam do mesmo conceito estávelEntidade ou contrato compartilhadoQue toda implementação deve ser compartilhada
UI coordena duas capacidadesCompositor superiorQue `shared` deve conhecer o domínio
Artefato usa segredo ou bancoEntrada server explícitaSua camada arquitetural
Somente uma rota usa o códigoManter perto da rota inicialmenteQue nunca virará feature

Heurísticas contextuais

Teste de remoção

Use para listar consumidores, rotas, testes, analytics e configuração. Resultado desejado: impactos visíveis, não “zero impacto”.

Regra de três

Use para atrasar abstrações. Ignore quando dois consumidores já têm semânticas diferentes ou quando um contrato estável é exigido.

Vocabulário do produto

Use nomes reconhecidos pelo time e pelo domínio. Não force verbos ou substantivos como classificação universal.

Exemplos que dependem do contexto

NomePode serPergunta útil
`dashboard`Rota agregadora ou domínio analíticoHá regras e roadmap próprios além da tela?
`settings`Rotas, feature ou grupo de capacidadesAs configurações mudam e são possuídas juntas?
`user`Entidade, perfil ou administraçãoEstamos modelando identidade, autoatendimento ou gestão?
`auth`Capacidade ampla ou fluxos separadosSessão, login e recuperação têm o mesmo owner?
Sinal de revisão

Se a decisão depende apenas de quantidade de arquivos, linhas ou desenvolvedores, falta evidência sobre responsabilidade e dependência.
