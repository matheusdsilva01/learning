Feature-Folders ou FSD?

Compare unidade de decomposição, vocabulário e custo de enforcement; não use tamanho da equipe como fórmula.

Mapa conceitual

QuestãoFeature-Folders pragmáticoFSD 2.1
Unidade principalCapacidade ampla do produtoSlice dentro de uma camada
Feature`cart`, com UI, estado e integraçãoInteração relevante, como `add-to-cart`
EntidadeOpcional para contrato transversalCamada formal para conceitos de domínio
Composição`app` e composers conforme necessidade`pages` e `widgets` com direção formal
API públicaPolítica local e entry points explícitosParte da metodologia por slice
GovernançaFerramentas configuradas pelo projetoSteiger + ferramentas gerais

Camadas FSD

app          inicialização e providers
pages        telas completas
widgets      blocos autônomos compostos
features     interações relevantes/reutilizadas
entities     conceitos de domínio
shared       fundação

processes    depreciada

Nem toda camada precisa existir. Slices da mesma camada normalmente não importam umas às outras. Relações entre entities têm uma exceção explícita `@x`, usada com parcimônia.

Next.js

app/                 # diretório especial do Next.js
  catalog/page.tsx
src/
  _app/              # camada FSD renomeada
  _pages/            # camada FSD renomeada
  widgets/
  features/
  entities/
  shared/

O prefixo evita confundir as camadas FSD `app/pages` com os diretórios do framework. `index.server.ts` pode separar APIs exclusivas do servidor. Isso não torna FSD e RSC a mesma arquitetura.

Use quando / evite quando

SituaçãoDireçãoMotivo
Capacidades amplas estão coesas e a matriz local resolve conflitosmantenha pragmáticoMais camadas não atacam um problema observado.
Entidades, interações e blocos compostos disputam ownershipavalie FSDO vocabulário formal pode reduzir ambiguidade.
Desejo de “parecer enterprise”não adoteNão há critério verificável.
Vários times precisam da mesma direção de dependênciafaça pilotoValide custo de migração e enforcement.
Código exclusivo de uma página sem reusomantenha na páginaFSD não exige transformar toda ação em feature.

Roteiro de decisão

  1. Descreva o conflito atual com exemplos.
  2. Modele como cada abordagem o resolveria.
  3. Compare imports, ownership, navegação e tooling.
  4. Faça piloto em um fluxo vertical.
  5. Registre benefícios observados e custos novos.
Steiger

O linter oficial do FSD permanece beta. Fixe versão e combine-o com TypeScript, ESLint e validações específicas do Next.js.
