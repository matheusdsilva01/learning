Lição 0007 / Teste

Observe o contrato pela interface.

Intercepte HTTP na fronteira e teste o que o usuário percebe, não a implementação do hook.

18–25 minutosResultado: teste de integração

O que MSW cobre

No Vitest com JSDOM, `setupServer` intercepta requisições emitidas pelo processo Node. Ele não inicia um servidor e não testa o backend real, banco, autenticação implantada ou chamadas diretas ao ORM.

// test/setup.ts
beforeAll(() => server.listen({ onUnhandledRequest: 'error' }))
afterEach(() => server.resetHandlers())
afterAll(() => server.close())

// feature handler — MSW 2
http.delete('/api/cart/items/:itemId', () => HttpResponse.json({ ok: true }))

Teste pelo comportamento

it('remove um item confirmado pela API', async () => {
  const user = userEvent.setup()
  render(<Cart />, { wrapper: createWrapper() })

  expect(await screen.findByText('Caderno técnico')).toBeInTheDocument()
  await user.click(screen.getByRole('button', { name: /remover caderno/i }))

  expect(await screen.findByText(/item removido/i)).toBeInTheDocument()
  expect(screen.queryByText('Caderno técnico')).not.toBeInTheDocument()
})

Esperar apenas o desaparecimento pode gerar falso positivo se a UI remove otimisticamente e depois faz rollback. Aguarde um estado que só ocorre após a conclusão ou teste separadamente sucesso e erro.

Prática

Dois caminhos

Implemente um teste de sucesso e outro de rollback. No segundo, sobrescreva o handler com `server.use` e responda 500. Ambos devem começar pela mesma ação do usuário.
