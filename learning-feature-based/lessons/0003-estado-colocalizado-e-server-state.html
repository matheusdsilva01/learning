Módulo 3 • Estado & Testes

Estado Co-localizado, Server State & Testes Automatizados

Como gerenciar cache isolado com TanStack Query, evitar stores globais poluídas e testar features com MSW.

⏱️ Tempo estimado: 7 minutos 🎯 Meta: Dominar Query Key Factory, Updates Otimistas e Testes de Integração Co-localizados

1. O Fim do Monólito de Estado Global

Durante anos, o padrão foi armazenar respostas de API em uma store global única (como Redux ou Context monolítico). Em Feature-Folders, dividimos o estado em categorias com ciclos de vida diferentes:

  • Server State (TanStack Query): Vive em features//api/. Não é estado da aplicação; é um cache temporário dos dados do backend.
  • Feature UI State (Zustand/Context): Vive em features//stores/. Controla interfaces efêmeras da feature (ex: drawer aberto, etapa de wizard).
  • URL State: Filtros e paginação que devem ser compartilháveis vivem nos parâmetros de busca da URL.

2. Simulador Interativo: Update Otimista & Rollback de Cache

Veja como o TanStack Query co-localizado na feature cart gerencia a interface em tempo real:

3. O Padrão Query Key Factory

Para que o cache da feature cart nunca colida com chaves de outras features e permita invalidação seletiva, usamos fábricas tipadas de chaves:

// src/features/cart/api/query-keys.ts export const cartKeys = { all: ['cart'] as const, details: () => [...cartKeys.all, 'detail'] as const, items: () => [...cartKeys.all, 'items'] as const, item: (id: string) => [...cartKeys.items(), id] as const, }; // Invalidação Cirúrgica ao Concluir Checkout: // Invalida apenas queries do carrinho, sem afetar o catálogo ou perfil queryClient.invalidateQueries({ queryKey: cartKeys.all });

4. Co-locação de Testes com MSW (Mock Service Worker)

No padrão Feature-Folder, os testes não ficam isolados em uma pasta raiz /tests distante. Eles residem ao lado dos próprios componentes e hooks:

// src/features/cart/components/__tests__/cart-drawer.test.tsx import { render, screen, waitFor } from '@testing-library/react'; import userEvent from '@testing-library/user-event'; import { createTestQueryClientWrapper } from '@/testing/test-utils'; import { CartDrawer } from '../cart-drawer'; describe('Feature: CartDrawer (Integration)', () => { it('permite remover item e atualiza o total via mutation', async () => { const { Wrapper } = createTestQueryClientWrapper(); render(<CartDrawer isOpen={true} onClose={vi.fn()} />, { wrapper: Wrapper }); // 1. MSW intercepta a chamada de API e entrega os dados mockados da feature expect(await screen.findByText('Tênis Esportivo')).toBeInTheDocument(); expect(screen.getByText('R$ 299,90')).toBeInTheDocument(); // 2. Simula ação do usuário const deleteBtn = screen.getByRole('button', { name: /remover/i }); await userEvent.click(deleteBtn); // 3. Verifica mutação e remoção do elemento na tela await waitFor(() => { expect(screen.queryByText('Tênis Esportivo')).not.toBeInTheDocument(); }); }); });
💡 Vantagem da Deleção Atômica com Testes Co-localizados

Quando a equipe decide descontinuar a feature cart ou substituí-la por uma integração de terceiros (ex: Shopify Storefront), basta deletar o diretório src/features/cart/. Nenhum teste órfão quebrado fica para trás na base de código.
