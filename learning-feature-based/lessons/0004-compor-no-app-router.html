Lição 0004 / Composição

A rota conhece a colaboração.

`catalog` apresenta produto, `cart` executa a ação e a camada `app` monta os dois sem dependência lateral.

15–20 minutosResultado: composição RSC segura

O erro a evitar

// Dentro de features/catalog — proibido pela política
import { AddToCartButton } from '@/features/cart'

Mesmo via API pública, esse import dá a `catalog` conhecimento de outra capacidade e permite ciclos futuros. O compositor já possui contexto para decidir que ação acompanha o produto.

Composição explícita

// app/catalog/page.tsx — Server Component por padrão
import { ProductCard } from '@/features/catalog'
import { listProducts } from '@/features/catalog/index.server'
import { AddToCartButton } from '@/features/cart'

export default async function CatalogPage() {
  const products = await listProducts()

  return products.map((product) => (
    <ProductCard
      key={product.id}
      product={product}
      action={<AddToCartButton productId={product.id} />}
    />
  ))
}

`AddToCartButton` pode ser Client Component. O Server Component cria o elemento e o passa como conteúdo renderizável. Evite passar uma render function comum através de uma fronteira Server→Client; funções comuns não são serializáveis pelo React.

Thin route é convenção

Next.js permite fetching e UI específica em `page.tsx`. Mantemos a rota fina para tornar a colaboração visível, não porque o framework proíbe lógica ali.

Quando criar um compositor

Se a mesma montagem aparece em várias rotas, extraia um módulo de camada superior, como `src/composers/catalog-with-cart`. Não o coloque em `shared`: ele conhece o domínio.

Prática

Fronteira dupla

Desenhe duas setas para cada import do exemplo: direção arquitetural e entrada no grafo client/server. Marque os dados que atravessam a fronteira React.
