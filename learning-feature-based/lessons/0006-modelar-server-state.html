Lição 0006 / Cache

O cache é uma réplica temporária.

Modele identidade e reconciliação antes de otimizar a sensação de velocidade.

18–25 minutosResultado: mutation com rollback

Chaves descrevem dados

export const cartKeys = {
  all: ['cart'] as const,
  detail: (cartId: string) => [...cartKeys.all, 'detail', cartId] as const,
}

// A variável usada pela queryFn participa da identidade.
useQuery({
  queryKey: cartKeys.detail(cartId),
  queryFn: () => getCart(cartId),
})

A factory centraliza convenção e inferência, mas não garante unicidade global. A equipe ainda precisa escolher raízes sem colisão.

Atualização otimista do cache

useMutation({
  mutationFn: removeCartItem,
  onMutate: async (itemId, context) => {
    await context.client.cancelQueries({ queryKey: cartKeys.detail(cartId) })
    const previous = context.client.getQueryData<Cart>(cartKeys.detail(cartId))

    context.client.setQueryData<Cart>(cartKeys.detail(cartId), (current) =>
      current ? { ...current, items: current.items.filter(i => i.id !== itemId) } : current
    )
    return { previous }
  },
  onError: (_error, _itemId, result, context) => {
    context.client.setQueryData(cartKeys.detail(cartId), result?.previous)
  },
  onSettled: (_data, _error, _itemId, _result, context) =>
    context.client.invalidateQueries({ queryKey: cartKeys.detail(cartId) }),
})

Retornar a Promise da invalidação mantém a mutation pendente até o refetch terminar. Invalidar marca a query como stale e normalmente refaz queries ativas; não significa remover o cache.

Concorrência

Um snapshot ingênuo pode sobrescrever outra mutation simultânea. Antes de usar optimistic update em fluxos concorrentes, modele identidade (`submittedAt`), ordenação e estratégia de reconciliação.

Escolha a técnica menor

Se o resultado otimista aparece em um único lugar, renderizar `mutation.variables` durante `isPending` evita alterar o cache e elimina rollback manual. Atualize o cache quando múltiplos consumidores precisam observar o resultado.

Prática

Falha primeiro

No laboratório, execute o teste de remoção com resposta 500. Confirme que o item reaparece e que a mensagem de erro é observável. Só então valide o caminho 200.

npm run testrollback
