Lição 0008 / Governança

A regra existe quando falha no arquivo errado.

Transforme a matriz em diagnósticos executáveis e teste casos permitidos e proibidos.

20–30 minutosResultado: lint + grafo aprovados

Duas ferramentas, dois tempos

JS Boundaries

Feedback por arquivo no editor. A versão 7 usa `boundaries/dependencies`; `element-types` e `entry-point` são APIs legadas.

Dependency Cruiser

Analisa o grafo e ciclos no CI. Capturas de `from.path` são reutilizadas em `to.pathNot` com `$1`.

Política, não magia

// Ideia central da política ESLint
{
  from: { element: { type: 'feature' } },
  allow: { to: [
    { element: { type: 'entity', fileInternalPath: 'index.ts' } },
    { element: { type: 'shared' } },
  ] },
}

O resolver TypeScript é parte da segurança. Sem resolver `@/features/...`, o plugin pode classificar um alias local como dependência externa e não aplicar a regra esperada.

// Dependency Cruiser: permite apenas a própria feature
from: { path: '^src/features/([^/]+)/' },
to: {
  pathNot: [
    '^src/features/$1/',
    '^src/entities/[^/]+/index\\.ts$',
    '^src/shared/',
  ],
}
Não ignore todos os testes

Testes também podem criar imports laterais ou profundos. Se uma exceção for necessária, limite-a a fixtures ou infraestrutura identificada.

Teste a regra

Uma configuração confiável possui fixtures: um import permitido deve passar; cada classe de violação deve falhar com a regra esperada. “Lint verde” só prova a política codificada sobre os arquivos incluídos.
