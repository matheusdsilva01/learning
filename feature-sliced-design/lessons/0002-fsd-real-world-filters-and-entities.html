Lição 0002 • Módulo 1: Aplicação Prática

Desmistificando Filtros Reais: Como Combinar Múltiplas Entidades sem Acoplamento

🎯 Objetivo da Lição: Aprender a resolver o cenário comum de painéis de filtro (ex: Catálogo de Filmes com busca por Categoria, Produtora e Ano) sem jogar código de domínio no shared/ e sem violar o fluxo de importações unidirecional do FSD.

1. O Dilema: Onde Colocar Selects Dinâmicos que Dependem de APIs?

Em um catálogo de filmes, precisamos filtrar por:

  • Categoria (dados vindos de /api/categories)
  • Empresa Produtora (dados vindos de /api/companies)
  • Título e Ano (filtros locais de texto)

Um erro comum é colocar esses dados dentro de shared/ ou colocar as chamadas de API de Categoria dentro de entities/movie. No FSD, nós mantemos o princípio de Entidades Independentes e Features Compositoras.

2. A Divisão de Responsabilidades no FSD

1️⃣ Shared (shared/ui/select)

Componente puro de UI (ex: <Select options={...} />). Ele não sabe o que é um Filme, Categoria ou Empresa. Recebe apenas label, options e onChange.

2️⃣ Entities Independentes (entities/category e entities/company)

Cada entidade possui seu próprio model/ com o hook do TanStack Query (ex: useCategoriesQuery). Elas não se conhecem e não dependem dos filmes.

3️⃣ Feature Compositora (features/filter-movies)

Importa o <Select /> do shared, consome os hooks de entities/category e entities/company e expõe o formulário/painel de filtros completo.

4️⃣ Widget do Catálogo (widgets/movie-catalog)

Renders a features/filter-movies e passa os filtros ativos para a query de filmes em entities/movie/model/useMoviesQuery(filters).

3. O Fluxo de Dados (Diagrama FSD)

[ widgets/movie-catalog ] / \ v v [ features/filter-movies ] [ entities/movie ] (useMoviesQuery) / | \ v v v [ entities/category ] [ entities/company ] [ shared/ui/select ] (useCategoriesQuery) (useCompaniesQuery) (<Select />)
