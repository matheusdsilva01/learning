Anatomia do FSD: Como Separar Entities de Features

🎯 Objetivo da Lição: Aprender a identificar com clareza o que pertence à camada entities/ (modelo de negócio puro) e o que pertence à camada features/ (ações do usuário com intenção comercial/fluxo), acabando com o acoplamento no Next.js.

1. O Problema da Organização por Domínio Tradicional

Quando organizávamos por pastas de domínio simples (ex: /src/user ou /src/cart), era muito comum que dentro da mesma pasta ficassem misturados:

  • O componente de visualização do avatar do usuário;
  • O formulário de edição de perfil;
  • As queries de busca de usuário;
  • As mutations de troca de senha.

Isso gerava baixo isolamento e alto acoplamento. No FSD, nós dividimos esse domínio em duas camadas hierárquicas com responsabilidades distintas.

2. A Regra de Ouro: Entity vs Feature

🏛️ Entities (Entidades de Negócio)

Representa substantivos do sistema. É o modelo de dados real, seus seletores, estilos visuais básicos (cards, badges) e as chamadas de busca de dados (useQuery).

Exemplos: user, product, order, category.

Regra: Uma Entity NUNCA sabe quem a está chamando ou qual ação está sendo executada com ela.

⚡ Features (Funcionalidades / Ações)

Representa verbos e intenções do usuário que trazem valor prático ao negócio. Costuma conter formulários, botões de ação, modais e chamadas de alteração de estado (useMutation).

Exemplos: add-to-cart, login-by-email, filter-catalog, update-user-avatar.

Regra: Uma Feature PODE importar e utilizar Entities para renderizar seus formulários ou ações, mas NUNCA o contrário.

3. Comparação Prática de Estrutura no Projeto

src/ ├── entities/ │ └── user/ <-- ENTIDADE USER (Substantivo) │ ├── ui/ │ │ └── UserAvatar.tsx <-- Apenas exibe o avatar e nome │ ├── model/ │ │ ├── userQueries.ts <-- TanStack Query: useUserQuery() │ │ └── types.ts │ └── index.ts <-- Public API (Encapsulamento) │ └── features/ └── update-user-avatar/ <-- FEATURE (Verbo/Ação) ├── ui/ │ └── AvatarUploadForm.tsx <-- Componente com botão e dropzone ├── model/ │ └── useUpdateAvatarMutation.ts <-- TanStack Query: useMutation() └── index.ts <-- Public API
⚠️ Regra da Public API (index.ts):
Um arquivo fora de entities/user só pode fazer:
import { UserAvatar } from "@/entities/user";
É PROIBIDO fazer importações profundas como:
import { UserAvatar } from "@/entities/user/ui/UserAvatar"; (Vaza detalhes de implementação!).
