Separe identidade e autoridade

Vitória concretaAo final, você conseguirá dizer qual valor localiza bytes, qual aparece na URL pública e qual concede poder de gestão.

Introdução

Saber “qual arquivo?” não responde “o que posso fazer?”

Identificadores localizam recursos. Credenciais demonstram autoridade. Um mesmo texto pode cumprir os dois papéis, mas misturá-los amplia o impacto de qualquer vazamento.

Uma aplicação pode usar um ID numérico para relacionamentos internos, um nome aleatório para localizar o blob, uma URL para leitura e um segredo para alteração ou exclusão. Esses valores apontam para o mesmo arquivo, mas não precisam conceder os mesmos poderes.

Pergunta de projeto: se alguém receber este valor, quais operações passa a conseguir executar? A resposta define se ele é apenas identificador, capacidade pública ou segredo de gestão.

No arquivo individual

O WaifuVault mantém vários nomes para o mesmo recurso

FileUploadService gera o token com uuid(). No upload multipart, o fileName vem do UUID usado anteriormente pelo storage; no upload por URL, FileUrlService usa o timestamp atual como nome-base. O modelo possui unicidade explícita para token; fileName é indexado, mas não tem restrição única no banco.

A resposta transformada por WaifuFile entrega token, url e id. O rótulo “public ID” usado pelo DTO para o número não muda o comportamento: são as rotas que determinam quais poderes cada valor realmente possui.

Duas rotas, duas finalidades

Leitura usa fileName; gestão usa token

  1. UploadO serviço cria o registro e devolve URL mais token.
  2. CompartilharO usuário entrega somente a URL pública ao destinatário.
  3. LerA rota /f resolve o registro pelo fileName.
  4. GerenciarAs rotas REST recebem o token de gestão.
  5. AplicarO poder disponível depende da rota que aceitou o valor.

O nome original na URL não concede autoridade adicional. Quando está presente, FileService.getEntry() exige que corresponda ao metadado armazenado; a busca principal continua sendo feita pelo nome interno.

Modelo de segurança

Posse do valor pode ser a própria autorização

Uma capacidade é uma credencial cuja posse autoriza uma operação. Ela não precisa dizer quem é a pessoa. No WaifuVault, as rotas REST do arquivo não exigem uma conta associada: apresentar o token correto abre consulta, alteração e exclusão. Há uma restrição adicional nas transições de senha de arquivos criptografados: mudar ou remover a senha também exige previousPassword.

A URL pública de um arquivo sem senha também funciona como capacidade de leitura. No multipart, o UUID torna o fileName difícil de adivinhar; no upload por URL, o timestamp usado como nome-base oferece menos imprevisibilidade. Em ambos os casos, quem conhece uma URL válida pode ler enquanto o arquivo existir.

Opaco

O valor não carrega significado de negócio legível. Um UUID não revela dono, tamanho ou expiração.

Imprevisível

Não deve ser possível derivar o próximo segredo observando os anteriores. Os tokens do projeto usam aleatoriedade criptográfica.

Escopo

Cada capacidade deveria conceder somente as operações necessárias ao destinatário.

Posse

Sem identidade adicional, copiar o valor equivale a transferir o poder associado.

Segredo

Uma URL pública pode ser opaca sem ser secreta; já um token de exclusão precisa permanecer restrito.

Revogação

O sistema precisa definir como encerrar a autoridade antes ou no fim da vida do recurso.

Menor privilégio: compartilhar o token do arquivo para permitir download também entrega alteração e exclusão. A URL pública concede uma autoridade menor e é o valor apropriado para leitura.

Buckets e álbuns

O próprio WaifuVault mostra uma separação mais profunda

No arquivo individual, esta revisão não oferece rotação isolada de token ou fileName. Expiração ou exclusão encerram as capacidades junto com o recurso. Adicionar senha muda a URL apresentada de /f para /p e pode trocar o host pelo frontend, mas preserva fileName e token REST. Trocar a senha de um arquivo já protegido mantém essa URL e também não revoga o token REST.

O bucketToken autentica a gestão de um bucket e é mantido na sessão após o login. Ele dá acesso amplo aos arquivos e álbuns daquele agrupamento. O README alerta explicitamente que essa chave não deve ser compartilhada.

Álbuns possuem dois valores distintos:

ValorFinalidadeRevogação
albumTokenIdentidade privada usada para administrar o álbum.Permanece estável enquanto o álbum existe.
publicTokenIdentidade compartilhável usada na URL pública.Ao descompartilhar, vira null; ao compartilhar novamente, recebe novo UUID.
  1. PrivadoO álbum existe com publicToken = null.
  2. CompartilharO sistema gera um UUID público novo.
  3. DistribuirA URL com esse UUID pode ser entregue a terceiros.
  4. RevogarDescompartilhar remove o token público atual.
  5. RenovarNovo compartilhamento cria outra URL pública.

Esse desenho revoga o acesso compartilhado sem trocar o identificador privado de gestão. A URL antiga deixa de localizar um álbum público, enquanto o administrador continua controlando o mesmo recurso.

Evidência: Album.model.ts e AlbumDao.setShareStatus().

Superfície de vazamento

Segredos em URLs atravessam muitos componentes

Tokens colocados no caminho podem aparecer no histórico do navegador, logs do servidor, proxies, ferramentas de monitoramento e capturas de tela. Dependendo da política de referência, uma URL também pode acompanhar a navegação para outro site. O uso de HTTPS protege o trânsito contra observadores da rede, mas não remove essas cópias nos extremos.

ValorTratamento coerente
URL pública de leituraPode ser compartilhada intencionalmente, mas ainda deve ser tratada como acesso ao conteúdo.
Token de gestãoNão compartilhar, não incluir em telemetria e evitar registrá-lo integralmente.
Chave de bucketTratar como credencial ampla; vazamento afeta muitos recursos.
ChecksumNão concede autoridade, embora possa revelar que um conteúdo conhecido está presente.

A OWASP Logging Cheat Sheet recomenda não registrar diretamente access tokens e identificadores de sessão.

Resumo de bolso

O que precisa permanecer

  • Identidade localiza um recurso; autoridade define operações permitidas.
  • Valores opacos precisam ser imprevisíveis quando sua posse concede acesso.
  • A URL pública do arquivo usa fileName; gestão REST usa token.
  • Um único token de consulta, alteração e exclusão possui autoridade ampla.
  • Capacidades públicas e segredos de gestão exigem tratamentos diferentes.
  • Separar token público de privado permite revogar compartilhamento sem perder gestão.
