Checksum: impressão digital dos bytes

Ideia centralOs mesmos bytes produzem o mesmo resumo. Mudar até um byte normalmente produz outro resumo completamente diferente.

Definição

Um arquivo grande vira um valor pequeno e comparável

Checksum é o resultado de aplicar uma função de hash aos bytes de um arquivo. A função percorre todo o conteúdo e produz um resumo de tamanho fixo.

Ele é determinístico: se a sequência de bytes for exatamente igual, o resultado será igual. Nome, pasta e data do arquivo não entram no cálculo, a menos que sejam incluídos explicitamente como bytes. Dois arquivos chamados foto.png podem ter checksums diferentes; dois arquivos com nomes diferentes podem ter o mesmo checksum se o conteúdo for idêntico.

bytes:     "conteudo privado"
MD5:       e06ecc14e49964d0a6d31dfb3da43d87

bytes:     "conteudo privado!"
MD5:       7931e1f83b02b6e2206380ed3d377f39
                              ↑ um caractere mudou

Não é compressão. O checksum não permite reconstruir o arquivo. Ele funciona como uma impressão para comparação, não como uma versão reduzida do conteúdo.

Modelo mental

O estado do hash avança a cada chunk

  1. AbrirO serviço abre um stream de leitura do arquivo.
  2. LerO filesystem entrega uma parte dos bytes por vez.
  3. AtualizarCada chunk modifica o estado interno do hash.
  4. FinalizarO fim do stream fecha o cálculo do resumo.
  5. CodificarO resultado binário vira texto hexadecimal.

Processar por chunks evita carregar o arquivo inteiro na memória. O algoritmo mantém apenas seu estado interno enquanto todos os bytes passam por ele. Isso não reduz a quantidade total lida: para resumir o arquivo completo, todos os bytes precisam ser observados.

No WaifuVault

Primeiro grava; depois abre o arquivo novamente

O checksum não é produzido por SizeLimitDiskStorage durante a chegada da requisição. Esse componente limita o tamanho e grava o stream recebido em um arquivo com nome interno. Quando ele termina, o caminho chega a FileUploadService.processUpload().

  1. UploadO cliente transmite o corpo multipart.
  2. GravaçãoO Multer salva os bytes no filesystem.
  3. ReleituragetFileHash() abre o arquivo salvo.
  4. MD5O hash recebe cada chunk e gera 32 hexadecimais.
  5. DecisãoUma duplicata ativa encerra o fluxo; sem reutilização, o processamento continua.
private getFileHash(resourcePath: string): Promise<string> {
    return new Promise((resolve, reject) => {
        const hashSum = crypto.createHash("md5");
        const stream = createReadStream(resourcePath);
        stream.on("data", (chunk: Buffer) => hashSum.update(chunk));
        stream.on("end", () => resolve(hashSum.digest("hex")));
        stream.on("error", reject);
    });
}

Código: FileUploadService.ts:331–339. A API Hash.update() aceita partes sucessivas e Hash.digest() finaliza o resumo: documentação do Node.js.

Consequência operacional: o arquivo é percorrido ao menos duas vezes: uma durante a gravação do upload e outra durante o cálculo do MD5. Filtros, detecção de MIME e criptografia opcional podem provocar leituras adicionais. Seria possível calcular o hash durante a primeira passagem, mas esse não é o desenho desta versão do WaifuVault.

Por que calcular

O mesmo resumo participa de decisões diferentes

Detectar repetição

O repositório procura registros com o mesmo checksum. O serviço restringe a reutilização ao bucket correspondente ou, fora de buckets, ao mesmo IP.

Evitar outra cópia

Se encontra um arquivo ativo no escopo permitido, o serviço remove o upload recém-gravado e devolve o registro existente.

Persistir metadado

Quando o arquivo é novo, o valor entra na coluna checksum de FileUploadModel, que possui índice para consultas.

Consultar reputação

Depois da persistência, uploads selecionados pela configuração entram em uma fila. Um worker usa o checksum para consultar um relatório já conhecido pelo VirusTotal.

Comparar conteúdo

Em geral, recalcular e comparar hashes ajuda a detectar alteração acidental. Nesta revisão, porém, não há uma verificação na entrega.

Não autorizar

Conhecer o checksum não concede leitura, alteração nem exclusão. Essas operações dependem de URLs, tokens e regras próprias.

A consulta de reputação depende de três configurações: chave da API, string de MIME types perigosos e limite de reputação. O upload é enfileirado depois de salvo; em execução posterior, o worker faz uma requisição GET usando somente o hash na URL, sem enviar novamente os bytes. Se a pontuação superar o limite, o arquivo é excluído.

Neste snapshot, a seleção usa dangerousMimeTypes.includes(mediaType ?? ""). Portanto, compara por substring em vez de separar uma lista de tipos exatos e também seleciona MIME desconhecido quando a configuração é uma string não vazia.

Fluxo de duplicatas: FileUploadService.ts:71–80 e 187–211. Enfileiramento: FileUploadService.ts:130–136. Consulta e exclusão: FileReputationService.ts:31–59 e 71–77.

Não confunda

Cada valor responde a uma pergunta

ValorPergunta respondidaPropriedade principal
Checksum“Estes bytes parecem ser os mesmos?”Deriva deterministicamente do conteúdo.
Nome interno“Onde o blob foi armazenado?”É gerado pelo servidor para localização.
Token“Quem pode executar esta operação?”Precisa ser imprevisível e tratado como capacidade.
Hash de senha“A senha apresentada confere?”É deliberadamente caro e usa algoritmo próprio, como Argon2.
Criptografia“Como impedir a leitura sem a chave?”Transforma os bytes e pode ser revertida com a chave correta.

No WaifuVault, o MD5 é calculado antes da criptografia opcional por senha. Quando a criptografia está habilitada, o checksum persistido descreve os bytes recebidos antes de o arquivo ser reescrito como conteúdo cifrado.

Limite de segurança

MD5 compara rapidamente, mas colisões podem ser fabricadas

Uma colisão acontece quando entradas diferentes produzem o mesmo resumo. Todo hash de tamanho fixo admite colisões em teoria, porque existem mais arquivos possíveis do que resumos. O problema específico do MD5 é prático: ataques conhecidos permitem construir colisões, então ele não deve sustentar assinaturas, identidade segura ou decisões adversariais que dependam de resistência a colisão.

O WaifuVault não compara os bytes depois de encontrar o mesmo MD5: dentro do escopo de deduplicação, ele considera o conteúdo repetido, apaga o upload novo e reutiliza o registro anterior. Uma colisão fabricada pode, portanto, causar uma falsa deduplicação. A consulta ao VirusTotal também recupera o relatório associado àquele MD5, não uma análise dos bytes recém-enviados.

A coluna possui índice para acelerar buscas, mas não uma restrição única. A deduplicação acontece na aplicação e não constitui, sozinha, uma garantia contra uploads concorrentes do mesmo conteúdo.

Leitura correta do código: o WaifuVault usa MD5 como chave operacional para deduplicação e consulta de reputação. Isso não transforma o checksum em prova criptográfica de identidade, autenticidade ou autorização.

A RFC 6151 afirma que MD5 não é aceitável quando resistência a colisões é necessária. Em um projeto novo, a escolha conservadora para integridade é SHA-256, mantendo tokens aleatórios separados.
